### 2.0 Population context

Phase one of the product path (Profiling standard, section 1, two paths): the nine designed tables hold rows generated by the phase-one generator (tutorial, knowledge 111 item 463, step 26), one set per round-one path of P-6, all for one data provider, client 3, and one month, October 2026. There are no real subscribers, no test records mixed with real ones, and no history: every row was written in one transaction on 2026-11-19 between 18:44:43 and 18:45:15 UTC, and none has changed since. Base population for each table's percentages is its own row count. Measured where the pipeline reads them, the Snowflake copies the Openflow connector made in `DATABP_LAB` (schemas `DATABP_SRC_DBO`, `DATABP_SFDC_DBO`, `DATABP_USAGE_DBO`), on 2026-11-19 from 19:27 to 19:30 UTC; every table's count there equals SQL Server's (tutorial step 26, 19:24:28 UTC), and no row is marked deleted. Because the data was designed, a column that holds one value does so by the phase's scope (one data provider, one month, one contract term), not by a defect of the source; P-11 records it. The connector's own columns `_SNOWFLAKE_INSERTED_AT`, `_SNOWFLAKE_UPDATED_AT` and `_SNOWFLAKE_DELETED` are the pipeline's metadata, not source columns, and are not profiled here.

Sub-populations: none. Each designed table describes one entity for one data provider; no routing column splits any of them.
